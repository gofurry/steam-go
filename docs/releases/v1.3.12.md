# v1.3.12 Release Notes — Draft

Status: **Unreleased**. These notes prepare the compatibility hotfix; no v1.3.12
tag or GitHub Release has been published by this work.

## Highlights

- Add `storefront.AppDetailsMatch`, `ResolveAppDetails`, and
  `Service.GetResolvedAppDetails` for strict requested-AppID identity matching.
- Restore Storefront media and free-package resolution when the outer key drifts.
- Doctor reports safely resolved key drift as WARN with diagnostic identity
  fields; it adds no failure and preserves exit code 0 when other checks succeed.
- Live smoke and the Storefront example consume resolved identity.

## Compatibility

The public API changes are additive; no breaking change is intended.
`GetAppDetailsRaw` retains raw bytes, `GetAppDetails` retains original envelope
keys, and `GetAppDetailsBatch` retains its public structure and per-item fetch
error semantics. Existing envelopes can be passed to `ResolveAppDetails`.

Resolution uses `data.steam_appid`. Missing or duplicate identity, unsuccessful
matches, and direct-key conflicts or missing identity fail closed, even when an
alternate entry looks valid. AppID 0 uses `KindRequestBuild`; identity failures
use the existing `KindAPIResponse`. Freeclaim retains its verification boundary.

## Upstream Incident

The [incident ledger](../governance/upstream-drift.md) records the confirmed
2026-09-26 AppDetails observations and the historical 2026-09-04 StoreBrowse
`assets.last_modified` type drift. The AppDetails cause and Valve's intent remain
unverified; these notes do not claim an official contract change.

## Boundaries

No response rekeying, first-entry fallback, DLC/parent/child inference, fallback
endpoint, scraping, or transport/retry/proxy/cache/rate-limit changes are part
of this hotfix. GoFurry is not modified. Live network validation is diagnostic
and opt-in; it is not a normal CI prerequisite.
